# TacStack v0.1 开发路线与架构

版本：2026-09 v2.0
开发周期：12 周（以单人、业余/半业余开发为基线）
第一原则：低成本、可验证、站在现有生态上，不重复造轮子

## 0. v0.1 的唯一目标

v0.1 不证明“我们能做一个完整触觉平台”。

v0.1 只证明一件事：

> **不同触觉数据源可以通过同一套 TacStack contract，稳定地产生可供机器人控制和调试使用的 contact / slip 等触觉语义事件。**

当 v0.1 完成时，一个新用户应该在 5 分钟内完成：

```text
下载一个 Open-X-Tactile 数据集
        ↓
TacStack Adapter 读取
        ↓
统一 TactileObservation
        ↓
contact / slip model runtime
        ↓
输出 TactileEvent
        ↓
Rerun 中同步查看触觉、机器人状态和事件
```

第 9-10 周以后，再接一块真实触觉传感器完成 live inference。

---

## 1. 明确不做什么

v0.1 不做：

- 自研电子皮肤硬件；
- 自研机器人本体；
- 自研灵巧手；
- 通用机器人数据平台；
- 自研 MCAP 替代格式；
- 自研 Rerun/Foxglove 替代 Viewer；
- 云 SaaS、多租户、登录、计费；
- 从零训练 tactile foundation model；
- 完整 VLA / world model；
- 一开始就做 C++ 全栈；
- 一开始支持 20 个传感器。

所有不直接验证 tactile semantic runtime 的功能，默认延期。

---

## 2. 产品定位

TacStack 位于现有机器人数据/控制生态的中间层：

```text
Sensor / Dataset
  ↓
TacStack Adapter
  ↓
Raw Tactile Data + Canonical Metadata
  ↓
Calibration / Sync / Quality
  ↓
Tactile Model Runtime
  ↓
TactileEvent
  ↓
ROS2 / Controller / Policy

旁路集成：
MCAP / Rerun / Foxglove / LeRobot
```

TacStack **拥有 tactile-specific semantics**，但尽量不拥有通用存储和通用 UI。

### 3.2 核心原则

#### Raw-first

不同 sensor 的 raw data 不强行压成一个矩阵。

保留：

```text
raw payload
canonical metadata
semantic derived output
```

#### Semantics-first

真正稳定的是：

```text
contact
slip
force
grip stability
quality
calibration
```

而不是厂商字段名。

#### Edge-first

闭环信号必须本地运行。

云端不是 v0.1 dependency。

#### Integration-first

优先适配 MCAP / Rerun / ROS2 / LeRobot，而不是重新建设这些能力。

## 4. 核心数据结构

### 4.1 SensorDescriptor

```python
@dataclass(frozen=True)
class SensorDescriptor:
    sensor_id: str
    vendor: str
    model: str
    modality: str
    frame_id: str
    sample_rate_hz: float | None
    capabilities: frozenset[str]
    schema_version: str = "1.0"
```

推荐 capabilities：

```text
tactile_image
taxel_force
normal_force
shear_force
wrench
temperature
imu
contact_mask
```

### 4.2 TactileObservation

```python
@dataclass
class TactileObservation:
    timestamp_ns: int
    sensor: SensorDescriptor
    raw: Any
    calibration_id: str | None = None

    tactile_image: np.ndarray | None = None
    taxels: np.ndarray | None = None
    taxel_positions_m: np.ndarray | None = None
    wrench: np.ndarray | None = None
    temperature_c: np.ndarray | None = None
    imu: np.ndarray | None = None

    quality: dict[str, float] = field(default_factory=dict)
    metadata: dict[str, Any] = field(default_factory=dict)
```

### 4.3 TactileEvent

```python
@dataclass(frozen=True)
class TactileEvent:
    timestamp_ns: int
    sensor_id: str
    kind: Literal[
        "contact_begin",
        "contact_end",
        "micro_slip",
        "slip",
        "stable_grasp",
        "unstable_grasp",
        "over_force",
    ]
    probability: float
    model_id: str
    latency_ms: float
    region: str | None = None
    vector: np.ndarray | None = None
    metadata: Mapping[str, Any] = field(default_factory=dict)
```

这个对象是 v0.1 最重要的 API。

### 4.4 ModelManifest

```python
@dataclass(frozen=True)
class ModelManifest:
    model_id: str
    version: str
    task: str
    required_capabilities: frozenset[str]
    window_ms: int
    runtime: str
    artifact_uri: str
    calibration_requirement: str | None
```

目的：模型可替换，但 runtime contract 不变。

## 5. Adapter 接口

```python
class TactileAdapter(Protocol):
    def descriptor(self) -> SensorDescriptor: ...
    def open(self) -> None: ...
    def close(self) -> None: ...
    def read(self) -> TactileObservation: ...
```

v0.1 Adapter 顺序：

1. `open_x_tactile`：零硬件成本，优先支持 2-3 种明显不同的数据源；
2. `mcap_replay`：形成统一 replay 路径；
3. `ros2_generic`：通过 mapping 把 ROS message 映射为 Observation；
4. `real_vision_tactile`：第 9-10 周加入一块真实视触觉传感器；
5. `xela_uskin` 等真实厂商 Adapter 留到 v0.2，除非有合作方提供硬件/数据。

## 7. 模型范围

### 7.1 Contact Baseline

目标：验证 Runtime 和事件 contract，而不是追论文 SOTA。

输入：1-5 帧。

输出：

```text
contact probability
contact_begin / contact_end
可选 contact region
```

### 7.2 Slip Baseline

Slip 必须视为时序问题。

视觉触觉 baseline：

```text
frame difference / optical flow
        +
small temporal CNN / lightweight temporal model
```

力/taxel baseline：

```text
force derivative / shear change
        +
1D temporal model
```

所有模型最后统一输出：

```text
micro_slip
slip
probability
latency
```

### 7.3 Embedding

v0.1 不训练 foundation model。

只预留：

```python
embedding = runtime.embed(observation_window)
```

v0.2 以后再封装公开模型。

# 10. 12 周开发路线

### 目标

先让“最重要的 API”可测试，再写功能。

- 建 GitHub repo；
- Python package；
- Apache-2.0 或暂定许可证；

- 定义 `TactileEvent`；
- 定义 `ModelManifest`；
- 写 ADR：为什么不做通用 data platform；
- 写 5 个最小 contract tests。

### Definition of Done

```bash
uv run pytest
uv run ruff check .
uv run mypy src
```

全部通过。

能够创建：

```python
obs = TactileObservation(...)
event = TactileEvent(...)
```

并完成 JSON/debug serialization。

### 不做

数据集下载器、模型、UI、ROS。

## Phase 1：第 1-2 周 - Open-X-Tactile 数据通路

### 目标

零硬件跑通真实 tactile data。

### Tasks

选择 2-3 个差异明显的数据源，例如：

```text
vision tactile
uSkin / taxel
robot force / torque
```

实现：

```text
OpenXTactileAdapter
EpisodeIterator
Timestamp normalization
Sensor descriptor mapping
```

CLI：

```bash
tacstack dataset list
tacstack inspect oxt:<dataset> --episode 0
tacstack convert oxt:<dataset> --episode 0 --out demo.mcap
```

### Definition of Done

- 同一套 `for observation in adapter:` 可以读取 2-3 类不同 sensor；
- raw 信息不丢失；
- timestamp 可排序；
- 单元测试包含固定 sample fixtures；
- 能导出一个可被 Rerun/Foxglove 打开的记录路径。

### 输出 Demo

“同一个 Python API 读三种不同 tactile source”。

---

## Phase 2：第 3-4 周 - Tactile DevTools / Annotation

### 目标

不造 Viewer，而是把 tactile semantics 加到 Rerun。

### Tasks

同步展示：

- tactile image / heatmap；
- force/taxel timeline；
- wrist RGB（数据集有时）；
- robot state；
- `TactileEvent` marker。

加入轻量 Annotation：

```text
C = contact
S = slip
U = unstable grasp
```

输出：

```text
annotations.parquet
```

### Definition of Done

- 一条 episode 可以按时间拖动；
- 至少 3 类 stream 同步显示；
- 标记 slip 后可以重新加载；
- annotation schema 带 user/version/timestamp。

### 输出 Demo

录 30-60 秒视频：

“视觉 + 触觉 + force + slip marker 同一时间轴回放”。

---

## Phase 3：第 5-6 周 - Contact + Slip Baseline

### 目标

证明 TacStack 不只是数据 Adapter，而是 Runtime。

### Tasks

Contact：

- baseline preprocessing；
- train/eval script；
- ONNX export；
- runtime inference；
- contact_begin/contact_end event。

Slip：

- temporal window；
- baseline optical-flow/frame-diff；
- lightweight temporal model；
- micro_slip/slip event。

CLI：

```bash
tacstack model run contact-v0 --input <episode>
tacstack model run slip-v0 --input <episode>
tacstack benchmark slip-v0 --dataset <dataset>
```

### Definition of Done

- 模型通过统一 runtime 调用；
- 模型文件和 manifest 分离；
- ONNX Runtime 能推理；
- 每个事件记录 latency/model_id/threshold；
- benchmark 可重复执行。

不要把模型准确率设为 v0.1 发布阻塞项，优先保证 pipeline 和可复现性。

---

## Phase 4：第 7-8 周 - Cross-sensor Contract + Quality

### 目标

证明不同 sensor 可以产生相同高层事件，而不强迫它们共享同一 raw representation。

### Tasks

- capability validation；
- calibration id；
- sample drop / jitter metrics；
- sensor health 基础指标；
- 两种不同 input modality 的 contact/slip pipeline；
- benchmark 输出按 sensor/model 分组。

### Definition of Done

控制程序可以只写：

```python
for event in runtime.events():
    if event.kind == "slip":
        ...
```

而不判断 sensor vendor。

### 决策门 Gate A

如果此时仍无法清晰解释“为什么不用现有项目直接完成”，暂停加功能，重新验证定位。

如果已有外部用户主动问 Adapter/数据支持，进入真实硬件阶段。

---

## Phase 5：第 9-10 周 - 第一块真实传感器

### 目标

把离线项目变成 live tactile runtime。

### 硬件原则

只买一块：

- USB/Python 友好；
- 输出易处理；
- 社区和文档清晰；
- 不依赖机械臂；
- 预算控制在个人可接受范围。

优先考虑视觉触觉类传感器；实际采购时再比较当时价格和供货。

### Tasks

- live adapter；
- 设备断连/重连；
- timestamp；
- live Rerun；
- live contact/slip inference；
- 本地记录 MCAP/原始文件；
- 手持采集 20-50 个物体。

动作：

```text
press
slide
twist
release
```

### Definition of Done

- 连续运行 30 分钟不崩；
- 实时画面 + tactile event；
- p95 pipeline latency 可测；
- slip 人工动作能明显触发；
- 一键 record -> replay -> inference。

### 不买

机械臂、灵巧手、高价 GPU。

# 12. 性能目标

v0.1 不追极限，但需要把性能变成可观测指标。

建议目标：

- timestamp：nanosecond integer contract；
- event pipeline：持续运行不丢异常；
- p95 inference latency：记录并可 benchmark；
- memory：长 episode replay 不无限增长；
- adapter drop/jitter：可统计；
- deterministic replay：同版本同输入可复现主要事件。

不要提前承诺固定毫秒 SLA，等真实硬件后建立 baseline。

# 14. API 稳定性

v0.1 发布前：

允许快速改 API。

v0.1 发布以后：

- `TactileObservation` / `TactileEvent` 变化需要 ADR；
- schema 增加版本；
- Deprecated field 至少保留一个 minor version；
- Sensor-specific 数据放 metadata/raw，不污染 core。

核心目标：让别人愿意依赖。

Go：

- Rerun 集成有良好 DevEx。

No-Go：

- TacStack 只是在给已有工具包一层薄 wrapper；
- 无法解释 tactile-specific value。

### Week 8

Go：

- 至少两类 sensor 能输出同一事件 contract；
- 有外部工程师表示愿意尝试。

Pivot：

- 用户真正痛的是 calibration / dataset conversion 而不是 runtime，则收缩到更强的单点产品。

### Week 12

Go：

- 外部用户能独立跑通；
- 有至少 1-2 个明确合作线索。

Slow down：

- 只有自己在用；
- 没有人愿意提交数据或 Adapter。

这样可以把项目当成低成本期权，而不是无限投入。

# 21. v0.1 成功定义

不要用 GitHub Star 作为唯一成功标准。

v0.1 真正成功，是达到下面至少四项：

- 3+ 不同 tactile data source；
- contact + slip runtime；
- 一块真实 sensor live demo；
- 一条统一 Rerun 调试链；
- 1 个外部 contributor；
- 3 个外部用户成功运行；
- 1 家厂商/实验室主动讨论 integration；
- 1 份真实 log 被外部用户交给你排查。

如果这些成立，就值得进入 v0.2。
